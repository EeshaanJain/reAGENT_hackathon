The method integration pipeline, end to end

Two lanes, one handoff. Given a paper's repo, this turns it into a tested, PR-ready Open Problems v3 (OP3) benchmark component — automatically reconstructing the environment, extracting a cited model contract, synthesizing an adapter, and running it through a battery of scientific checks before any human reviews it.

Companion to README.md (exact commands + output locations), contract_gen/README.md, benchmark_adapt/README.md, and benchmark_adapt/tools_spec.html (deep dive on the Stage 4-6 tools specifically).

1The two lanes

contract_gen — Stage 0-3

Understand the model

  • Ingest: clone + pin a commit
  • RepoLaunch: real, LLM-driven environment reconstruction → a built Docker image
  • Repo comprehension: cited static-analysis signals (heuristic stand-in for Serena)
  • Contract synthesis: a schema-valid, citation-disciplined model_contract.yaml
benchmark_adapt — Stage 4-6

Wire it into the benchmark

  • Adapter synthesis: an agent writes script.py against the contract
  • The Gauntlet: 6 checks, running that one script 4 different ways
  • Human review, then a PR — never an auto-merge

2The mechanism

contract_gen (Cecilia's lane) benchmark_adapt (Sei's lane) agent step (non-deterministic, costs money) verification (deterministic)

3What's new in each lane

LaneToolRole
contract_genRepoLaunchReal, vendored, pinned by commit (not on PyPI). Its own LLM agent explores an unfamiliar repo and builds a working Docker image + reconstructs a Dockerfile from the image's actual layers. Needs Python >= 3.12 -- lives in its own venv, separate from the shared reagent env.

4Worked example: CPA

CPA (theislab/cpa) is the test case run through this pipeline live, specifically because it needs raw single-cell counts as input -- the concrete, real instance of the OP3 API gap discussed throughout the plan docs (see PR #78, which hit exactly this wall trying to integrate the same model).

What the heuristic comprehension stage found, from real grep evidence

requires_sc_counts:
  value: true
  citation: repo:cpa/_api.py:L10        # matched "setup_anndata" -- a single-cell-model convention

prediction_level:
  value: single_cell
  citation: repo:cpa/_api.py:L10

perturbation_encoding:
  value: smiles
  citation: repo:cpa/_model.py:L7       # matched "SMILES" reference

No LLM call was needed to find this — a static grep pass over the real, cloned theislab/cpa repository at a pinned commit surfaced it directly. Once benchmark_adapt reads a contract with requires_sc_counts: true, the seeded adapter template includes an explicit note about the gap instead of a silent workaround that would produce wrong scores. That's the correct, intended outcome for this case — not a failure to fix.

Full run, actually executed: driven by a real Paperclip record (contract_gen/fixtures/paperclip_cpa_record.json) through harness.orchestrator --paperclip-record ..., RepoLaunch really built the image (status PASS), and the handoff to benchmark_adapt produced a stub adapter with the gap explained inline plus a drafted (not submitted) PR — see methods/benchmark_adapt/output/cpa/PR_DESCRIPTION.md.
