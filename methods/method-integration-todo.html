Method Integration Agent · build plan

What to build, in what order, and what still needs a decision

A to-do list derived from methods/METHOD_INTEGRATION_AGENT.md, reconciled against plan_unified.md and plan_sei.md. 39 items across 8 blocks, each with an acceptance check and its blockers. Then the 11 places the plan is not yet buildable as written.

Sources: reAGENT_hackathon@method (9a20021) — MD 165 lines, unified plan 227 lines, Sei plan 128 lines. Tool availability verified live against the GitHub and PyPI APIs.

Scope, restated from the source doc

“Automatically adapt a published perturbation model to an already-defined benchmark. This component does not design datasets, splits, or metrics.” — MD L5–7

On this list

  • Dataset adaptation → the benchmark’s typed API
  • Validation: the Gauntlet + provenance artifacts

Not on this list

1The one ordering fix to make before anything else

The MD’s workflow diagram runs context → repo understanding → contract → then a parallel fork into environment build and dataset adapter. The unified plan reverses the first two, and it is right to: Serena is a language-server client, so find_symbol resolves nothing until the dependencies are actually installed. Comprehending before building yields confidently wrong entrypoint guesses.

2Where the work sits

Weight is concentrated in two places: reconstructing the environment (block C) and proving the adapter didn’t silently change the science (block G). Both are places where “it ran” and “it’s correct” come apart.

3The to-do list

Each item carries an acceptance check — the thing that has to be true for it to count as done — and its blockers. Tags: Build write it, Reuse take it as-is, Verify prove an assumption, Decide a human has to choose before code can be written.

APre-work — before any agent runs5 items · hours 0–3 · both owners together
A1Hand-write one adapter for an existing OP3 method
Done when: viash ns test --query <method_id> passes on a component you wrote by hand. This is the golden reference the agent’s output gets compared against, and how you learn the Viash contract.
Blocks: F1, F2, G1–G7, H3. Nothing downstream is meaningful without it.
Build
A2Build the tiny fixture and freeze its gene order
Done when: a ~200 cell × 500 gene slice with 3 compounds and 2 cell types loads in under a second, and its gene order is recorded as a SHA256 that tests assert against.
Blocks: F1 (the synthesis loop iterates against this), G1, G2.
Build
A3Reproduce OP3’s six control methods from a clean checkout
Done when: all six run end-to-end locally and their scores are written down. They are the baselines — the plan is explicit that a new method failing to clear them is expected, not a bug.
Blocks: G5, H3 (you need the between-method score spread to compare K=3 against).
Verify
A4Turn the Upstream Contract into a runnable ingest check
Done when: a script hard-fails on a missing field. The MD lists seven required inputs as prose; make them assertions — paper text, repo URL, pinned commit SHA (never main), split definition, dataset schema, hidden-test policy, metric spec, allowed external priors, license, declared modality.
Blocks: B1, B2. Catches upstream problems before you spend agent tokens on them.
Build
A5Write MODELSPEC.json as an actual JSON Schema
Done when: a validator accepts "unknown" for any field, rejects a field with no citation, and rejects a field whose citation doesn’t resolve. Union the MD’s model_contract.yaml with the unified plan’s richer schema — they are the same object and should stop having two names.
Blocks: E1, E3, E4. Everything downstream reads this file.
Build

B1Snapshot vendoring script
Done when: vendor/<method_id>/ exists at the pinned SHA with the commit and tree hash recorded, and the build works with the network off.
Depends on A4. Blocks C1–C4.
Build
B2Paperclip context pack with resolvable line citations
Done when: methods and results sections are extracted line-numbered under a stable PAPER_ID, and a citation like PAPER_ID:L120-134 in the contract can be mechanically resolved back to its text. Citations that can’t be checked are decoration.
Depends on A4. Blocks E1.
Build
B3Decide the full-text-unavailable degradation path
Done when: it is written down what happens with abstract-only access — the answer should be “affected contract fields become unknown”, never “the agent infers them”. This is one of the plan’s four open questions and it changes the agent’s prompt.
Blocks E1. Owner: needs Philipp’s input on how often it bites.

CStage 1 — Environment build (RepoLaunch)6 items · the critical path and the highest-risk block
C1Vendor and pin RepoLaunch by commit — it is not on PyPI
Done when: RepoLaunch installs reproducibly from a vendored checkout at a fixed SHA. Verified: pip install repolaunch returns 404, while the other four stack tools all resolve. Its run instructions live in docs/Development.md, not the README.
Blocks C2, C3, C4, D1 — i.e. the whole comprehension lane.
Build
C2Configure RepoLaunch’s own LiteLLM provider, key, and cost logging
Done when: one successful launch on a throwaway repo, with tokens and wall-clock written into execution_log.json. RepoLaunch is itself an LLM agent — it is a second model integration with its own config surface and its own cost, not a library call.
Depends on C1. Feeds the cost/wall-clock deliverable owed to Eeshan and Sundial.
Build
C3Deterministic Dockerfile → engines.docker.setup transform
Done when: the same reconstructed Dockerfile produces a byte-identical Viash setup block on two runs. RepoLaunch emits the image plus layer info for Dockerfile reconstruction; a plain function converts it. The agent never hand-writes the Dockerfile.
Depends on C1. Blocks F2.
Build
C4Clean-rebuild check
Done when: the image rebuilds from the emitted setup with no cache, and every dependency plus the repo commit is pinned. This is the MD’s first robustness check made executable.
Depends on C3.
Verify
C5Decide GPU or CPU-only for the difficulty ladder
Done when: written down, with Modal either scoped in or explicitly dropped. The plan’s own assessment is that RepoLaunch plus CUDA is the single biggest schedule risk, and that CPU-only is preferred — this decision also picks which papers can be on the ladder at all.
Blocks H4 (ladder selection) and the Modal line item.
Decide
C6Sandbox policy: restricted credentials and filesystem
Done when: the SWE-ReX execution profile mounts only the fixture, carries no credentials the repo could exfiltrate, and blocks network egress at inference. Straight from the source doc: “run unfamiliar repositories in a sandbox/container with restricted credentials/filesystem access.”
Blocks G4. Applies to every stage that executes vendored code.

EStage 3 — Contract extraction5 items · this is the project’s actual contribution
E1Contract-extraction agent: typed, cited, unknown is legal
Done when: the agent fills the schema from A5 with every field citing PAPER_ID:Lstart-Lend or repo:file:line, and leaves fields unknown rather than guessing. A confident wrong value here silently corrupts every score downstream.
Depends on A5, B2, D1. Blocks the handoff.
Build
E2Scope defense: refuse genetic methods, don’t adapt them
Done when: a genetic-perturbation paper fed to the chemical task produces a labeled rejection record returned upstream, not an adapter. perturbation_encoding: gene_id → refuse. Rejections are useful eval data for the literature agent; a heroic adaptation is a failure that looks like a save.
Depends on E1.
Build
E3Resolve the gene-order default — the two docs contradict each other
Done when: one default exists. The MD ships gene_order_fixed: false (permissive) while the Gauntlet makes any use of the metric’s --resolve_genes rescue a hard fail. Recommend: default to unknown, treat order as significant until a citation says otherwise.
Blocks G2. A5 encodes whatever you decide.
Decide
E4Give hyperparameters a real schema and a runtime assertion
Done when: the field has typed keys and the values are asserted at runtime, with mismatches logged as deviations. Today it is {...} in both plans, described as “asserted at runtime” with nothing to assert against — which is how an agent quietly cuts epochs to make a run finish.
Depends on A5. Feeds E5.
Build
E5DEVIATIONS.md emitter
Done when: every divergence from the paper’s stated protocol has a row, and an empty file is only legal alongside an explicit “no divergences” assertion. This artifact replaces “numerical agreement with the paper” as the scored criterion — the question is whether the gap is explained, not whether it exists.
Depends on E1, E4. Feeds H2.
Build

Done when: the adapter names its output layer and asserts it. The silent killer: the model emits logFC while the metric expects clipped_sign_log10_pval bounded at ±4 — garbage scores, zero errors, nothing in the log.

Done when: shuffling compound labels changes the prediction by more than a written-down threshold. Catches a model that has collapsed to the training mean. The threshold is currently the word “materially” in both plans; pick a number before you need it.

4What needs work — the plan’s 11 soft spots

The MD is a good tool-selection memo. What it is not yet is a build plan: most items have no acceptance criterion, and a handful of specifications actively contradict each other or a sibling document. Ordered by how much damage each one does if it survives to execution.

◆Critical
The workflow diagram has the two hardest stages in the wrong order
The MD draws context → comprehension → contract → a parallel fork of environment build and dataset adapter. The unified plan runs environment build before comprehension, and that is the correct order: Serena’s symbol resolution needs installed dependencies. Build them backwards and you get plausible, wrong entrypoint guesses that survive all the way to a score.
Fix: D4 — edit the ASCII diagram. Minutes of work, and it is the highest-leverage edit in the document.
◆Critical
RepoLaunch is simultaneously the critical path and the least available tool
Everything in the comprehension lane sits behind it, and it is the only one of the five stack tools with no PyPI package (verified 404, against 200 for mini-swe-agent, serena-agent, swe-rex, and modal). It is also the oldest last-push in the stack, it needs its own LiteLLM provider and key because it is itself an LLM agent, its run instructions are in docs/Development.md rather than the README, and its native target is build-and-test repos — a research repo with no test suite yields an empty testcase-status map. On top of that, the plan itself names RepoLaunch + CUDA as the biggest schedule risk.
Fix: C1, C2, C5 — vendor and pin by commit, budget for a second model integration, and have a manual-install fallback ready for at least one ladder rung.
▲Serious
The gene-order default and the gene-order gate disagree
The contract template ships gene_order_fixed: false. The Gauntlet makes any use of the metric’s --resolve_genes rescue a hard fail. So the permissive default invites exactly the adapter the gate is designed to reject — and the failure mode in between is silently misaligned genes, which produces numbers rather than errors.
Fix: E3 — default to unknown, treat order as significant until cited otherwise.
▲Serious
The benchmark API can’t express a whole class of the models you want to integrate
OP3’s method API passes only de_train and id_map. That fits the six Kaggle-derived methods, and cannot express chemCPA, CPA, or biolord, which need single-cell counts living upstream of process_dataset. The current answer is to dodge it by picking API-compatible methods for the demo, plus an unfiled proposal for --sc_train. The dodge is the right call for a hackathon; leaving the proposal unwritten is not, because the gap is the most transferable finding here.
Fix: H4, H6 — demo the rung that fails, and file the API-gap proposal as a written artifact.
▲Serious
Nobody owns the results table that everything is supposed to land in
Deviations are meant to “surface as a column in the results table”, the K=3 comparison needs a place to live, and baselines need to sit beside the generated method. No document names that file, its schema, or its owner — and a harness that runs models but writes no single comparable table is how a benchmark becomes quietly non-comparable.
Fix: H2 — one tidy long-form table, one owner, and a first-class status column so failures are rows rather than absences.
●Warning
“Reproducible within an explicitly defined stochastic tolerance” — the tolerance is never defined
It appears as a robustness requirement with no number, in either document. Since GPU determinism was explicitly cut from scope, bitwise identity isn’t available, which makes the tolerance the only version of this check that can exist.
Fix: G7. Also blocks a clean read of the K=3 headline.
●Warning
The headline result has no pre-registered decision rule
“If K=3 adapters spread as widely as the gap between models, the pipeline is measuring itself” is the most valuable number the workstream can produce in a day — and “as widely as” is doing all the work. Decide the threshold before the runs, or the conclusion gets fitted to whatever comes out.
Fix: H3, after A3 gives you the between-method spread to compare against.
●Warning
The five experiments are directions, not tests
README-only vs Serena+paper, manual install vs RepoLaunch, the difficulty ladder, generated vs gold, and the cost/retry tracking all lack a success threshold. With a fixed time budget and no threshold, every experiment resolves to “we observed some things”.
Fix: H5 — one number per experiment, written before the runs.
●Warning
hyperparameters: {...} is a placeholder doing load-bearing work
It is described as “asserted at runtime, deviations logged”, but there is no schema to assert against. This is the field that catches an agent quietly cutting epochs to make a run finish inside the time budget — the exact failure DEVIATIONS.md exists to prevent.
Fix: E4.
●Warning
The first three hours are a single point of failure
Everything downstream assumes a hand-written golden adapter and working Viash fluency. If A1 slips, stages 4 through 6 have nothing to be compared against and the Gauntlet has no reference. It is also the one block that can’t be parallelized away — both owners need the same contract knowledge.
Fix: A1 first, on a control method (the fastest path to a working contract), and timebox it hard.
●Warning
Four open questions are still open, and three of them gate real work
Which OP3 method to hand-write first (gates A1); the Chem-PerturBridge checkpoint license, since an unlicensed checkpoint can’t go in a public PR (gates H6); GPU or CPU-only (gates C5 and ladder selection); and whether the full-text access blocker reaches this workstream or stops at the literature agent (gates B3).
Fix: answer all four before hour zero — none of them need new information, only a decision.
What the plan already gets right — don’t relitigate these

The MODELSPEC.json ≡ model_contract.yaml equivalence is stated explicitly, so the two names are a labelling nuisance rather than a design conflict. Per-field citation to PAPER_ID:Lstart-Lend or repo:file:line is already required. Metric design, dataset QC, and the leakage audit are named as other people’s work. Hidden-test protection is structural in OP3 rather than something you enforce. Baselines are reused, not rebuilt. And “numerical agreement with the paper” has already been correctly dropped as a scored criterion in favour of “does DEVIATIONS.md explain the gap?”. That last swap is the single best judgement call in the document.

The MVP recommendation is right, and worth defending

mini-SWE-agent + Serena MCP + RepoLaunch + SWE-ReX, Docker locally, Modal only for GPU. Four of those five are pip-installable and permissively licensed, which means the project’s scarce time goes where the doc says it should: contract extraction, dataset adaptation, and validation — not rebuilding coding-agent or container infrastructure. Every hour spent on orchestration plumbing is an hour not spent on the only three things nobody else can supply.

6Suggested order of attack

  1. Answer the four open questions (H5 inputs, C5, A1 target method, checkpoint license). None need new information.
  2. Fix the diagram (D4). Minutes, prevents a wasted day.
  3. Hand-write the golden adapter and build the fixture (A1, A2, A3). No agents yet.
  4. Write the schema and the ingest check (A5, A4) — these define what “done” means for the agent stages.
  5. Get RepoLaunch working on one easy repo (C1–C4). If this slips, everything slips; find out early.
  6. Then, and only then, wire Serena (D1) and the contract-extraction agent (E1).
  7. Gauntlet tests before the adapter agent (G1–G6). Tests written after the code they judge tend to agree with it.
  8. K=3 and the ladder last (H3, H4) — they are results, and they need everything above to be trustworthy.
